Required interfaces/content structure:
- **`scripts/vm/verify.sh`** (read-only checks, never mutates the system except its own hardlink test files):
  - Skeleton: `set -Eeuo pipefail`, sources `common.sh`, `usage`, `parse_common_args` (it accepts `--apply` but ignores it), `load_env`.
  - Vars: `DATA_ROOT` (default `/data`), `SKIP_HW` (default `0`), `RENDER_NODE` (default `/dev/dri/renderD128`).
  - Helper functions `pass <id> <detail>`, `fail <id> <detail>` and `skip <id> <reason>` print `PASS <id> <detail>` / `FAIL …` / `SKIP …` to stdout and increment counters. Checks must not abort the script on failure; wrap each so `set -e` doesn't exit early.
  - Checks, in this exact order:
    1. `gpu`: `RENDER_NODE` is a character device. Detail includes `uname -r`. On FAIL, the detail says `see docs/runbooks/01-proxmox-host.md#5-troubleshooting`.
    2. `vaapi-av1`, `vaapi-hevc`, `vaapi-h264`: run `vainfo --display drm --device "$RENDER_NODE" 2>/dev/null` once and grep the regexes from the spec:
       - `VAProfileAV1Profile0.*VAEntrypointEncSliceLP`
       - `VAProfileHEVCMain10.*VAEntrypointEncSlice`
       - `VAProfileH264Main.*VAEntrypointEncSlice`
       If `vainfo` is missing, FAIL all three with "vainfo not installed".
    3. `data-mount`: `findmnt -n -t virtiofs "$DATA_ROOT"` succeeds. With `ALLOW_NFS=1`, `-t nfs,nfs4` is also accepted, to support the runbook's NFS fallback.
    4. `tree`: all 15 entries (the same list as `mkdirs.sh`) exist under `DATA_ROOT`. On FAIL, the detail lists the missing ones.
    5. `hardlink`:
       - Create `"$DATA_ROOT/usenet/complete/.verify-hardlink-$$"`, then `ln` it to `"$DATA_ROOT/media/.verify-hardlink-$$"`.
       - Compare `stat -c %i` of both. Equal inodes and a link count of 2 is PASS; otherwise FAIL with both inodes.
       - Always remove both files (trap-safe).
    6. `docker`: `timeout 5 docker version --format '{{.Server.Version}}'` succeeds, and `timeout 5 docker compose version` succeeds. A timeout counts as "daemon unreachable". Wrap every docker call in checks 6-8 with `timeout 5` (15 for `compose config`).
    7. `network`: `docker network inspect proxy` succeeds.
    8. `compose`: `docker compose -f "$REPO_ROOT/compose.yaml" config -q` succeeds. If `$REPO_ROOT/.env` is missing, FAIL with "copy .env.example to .env".
  - `SKIP_HW=1` behavior:
    - `gpu`, `vaapi-*` and `data-mount` are SKIP with reason `SKIP_HW=1`.
    - `docker`/`network`/`compose` are SKIP with reason `docker unavailable (SKIP_HW=1)` only when `docker` is not on PATH, or its server is unreachable.
    - When docker works, `docker`/`compose` run normally, and `network` is SKIP if the proxy network is absent (a CI runner won't have it).
  - Final line `RESULT: <p> pass, <f> fail, <s> skip`. Exit 1 if f > 0, else 0.
- **`scripts/ci/check-pinned-images.sh [compose-file]`** (default `compose.yaml`):
  - Uses `docker compose -f "$file" config --images`. If that subcommand is unavailable, fall back to `docker compose -f "$file" config --format json` parsed with `python3 -c` to list `.services[].image`.
  - For each image, OK if it contains `@sha256:`, or if its final path component contains `:` and the tag is not `latest`. Otherwise print `UNPINNED: <image>`.
  - Exit 1 if any image is unpinned. Print `OK: <n> images pinned` (n may be 0) and exit 0 otherwise.
- **`.yamllint.yaml`**:
  ```yaml

    line-length:
      max: 160
  ```

- **`.github/workflows/lint.yml`**:
  - `name: lint`
  - `on: {push: {branches: ['**']}, pull_request: {}}`
  - `permissions: {contents: read}`
  - One job `lint` on `ubuntu-latest`. Steps:
    1. `actions/checkout@v4`
    2. `cp .env.example .env`
    3. `docker compose config -q`
    4. `scripts/ci/check-pinned-images.sh`
    5. `sudo apt-get update && sudo apt-get install -y shellcheck`, then `shellcheck -x scripts/lib/common.sh scripts/mkdirs.sh scripts/host/*.sh scripts/vm/*.sh scripts/ci/*.sh`
    6. `pip install yamllint && yamllint -s .`
    7. Sandbox: `d=$(mktemp -d); DATA_ROOT=$d/data APPDATA_ROOT=$d/appdata scripts/mkdirs.sh; DATA_ROOT=$d/data SKIP_HW=1 scripts/vm/verify.sh`
    8. Host-script dry-runs against stubs: `d=$(mktemp -d); scripts/ci/make-host-stubs.sh $d/bin; PATH=$d/bin:$PATH scripts/host/00-zfs-datasets.sh; PATH=$d/bin:$PATH scripts/host/20-create-vm.sh`
    9. Executable bits: `test -z "$(find scripts -name '*.sh' ! -path 'scripts/lib/*' ! -perm -u+x)"`. `actions/checkout` restores git file modes, so this catches scripts committed without mode 100755.
  - Use `shell: bash` defaults.
  - Pin the action by major tag `@v4`. GitHub Actions are not images, so they aren't covered by check-pinned-images.
Edge/error cases:
