# Phase 3: Edge & Secure Access -- Context

## Phase Goal
Safe public access for Seerr and Authentik over Traefik on 443 (Plex stays direct on 32400; Jellyfin public only if adopted later), DDNS for the dynamic IP, and every admin UI reachable only as *.int.<domain> through Twingate, behind the lan-only allowlist plus Authentik forward-auth with admin MFA, with CrowdSec and geo-block on the public routes.

## Requirements Covered
- R6 Edge: Traefik v3, wildcard certificates via Cloudflare DNS-01, cloudflare-ddns (DNS-only records), Authentik (invites, admin MFA), CrowdSec bouncer, geo-block, secure headers. Only ports 443 and 32400 are forwarded.
- R7 Private admin: Twingate connector already in LXC 101 (no container); admin UIs under *.int.<domain> behind the lan-only ipAllowList plus Authentik forward-auth.

## Key Design Decisions
- Approach: Pragmatic (owner choice 2026-10-14 after Minimal/Clean/Pragmatic proposals). Script and version what is cheap and safe; one-time UI choices stay in the runbook.
- Seerr auth: Plex login only at requests.<domain>, no Authentik forward-auth in front (owner choice). Compensated by CrowdSec, geo-block, rate limit and secure headers on its router.
- Traefik static config as `command:` flags in stacks/edge.yaml; dynamic config from Docker labels read through a read-only docker-socket-proxy (Traefik never mounts docker.sock), exposedByDefault=false; a file provider (config/traefik/dynamic/, mounted read-only) holds only TLS options (min TLS 1.2, sniStrict).
- One entrypoint `websecure` on :443 (published 443:443), no :80 entrypoint, no HTTP/3. Internal `ping` entrypoint :8082 for the healthcheck, not published.
- Certificates: one ACME resolver `cloudflare` with dnsChallenge (resolvers 1.1.1.1:53,1.0.0.1:53), domains main=${DOMAIN}, sans=*.${DOMAIN},*.int.${DOMAIN}; ACME_CASERVER selects LE staging for the first run; acme.json under ${APPDATA_ROOT}/traefik/acme.
- Middlewares are defined once as labels on the traefik service and composed into two chains; other services only reference a chain: `int@docker` and `public@docker`. 03-01: int = lan-only, secure-headers; public = rate-limit, secure-headers. 03-02 appends authentik to int. 03-03 prepends crowdsec, geoblock to public.
- lan-only = ipAllowList sourceRange ${LAN_CIDR} (LXC 101 is inside the LAN, so no separate Twingate IP); no forwardedHeaders.trustedIPs (no CDN in front), IPv4 only.
- Hostnames: admin UIs <service>.int.${DOMAIN} (sabnzbd, prowlarr, sonarr, sonarr-anime, sonarr-4k, radarr, radarr-4k, lidarr, tautulli, traefik dashboard, jellyfin under its profile); public requests.${DOMAIN} (Seerr) and auth.${DOMAIN} (Authentik); plex.${DOMAIN} is only a DDNS record (Plex 32400 direct, no router). *.int.${DOMAIN} is a DNS-only Cloudflare wildcard A record to the VM LAN IP plus a Twingate resource (owner steps).
- cloudflare-ddns: favonia/cloudflare-ddns, A records only for plex, requests and auth, PROXIED=false, IP6_PROVIDER=none, UPDATE_CRON=@every 5m.
- Secrets are files under secrets/ declared as Compose top-level secrets: cf_dns_api_token (owner pastes a token scoped Zone:DNS:Edit on one zone), authentik_secret_key, authentik_pg_password, authentik_bootstrap_password, crowdsec_bouncer_key. scripts/vm/40-edge-secrets.sh (dry-run default, --apply) generates the random ones, never overwrites, never prints values, mode 0400 owned PUID:PGID.
- Authentik: server + worker (same pinned image) + pinned Postgres on a dedicated `authentik` network (Postgres not on proxy); embedded outpost; blueprints in config/authentik/blueprints/ mounted at /blueprints/custom for the domain-level forward-auth provider, application, outpost binding, `admins` group, admin-only MFA (configure if missing) and an invitation enrollment flow; the owner enrols MFA, creates invites and keeps a recovery key. /if/admin on auth.${DOMAIN} is LAN-only.
- CrowdSec engine reads Traefik's JSON access log; bouncer is the Traefik plugin maxlerebourg/crowdsec-bouncer-traefik-plugin (stream mode, key from file) and geo-block is the plugin PascalMinder/geoblock (allowLocalRequests, countries from GEO_ALLOWED_COUNTRIES), both pinned by version and on public routers only. crowdsec shares a dedicated `crowdsec` network with traefik only.
- Every new image pinned to an exact current stable tag confirmed to exist in its registry (never latest). Plans run one per wave (all three edit stacks/edge.yaml). compose.lan.yaml is deleted last (03-03), after forward-auth works, so the owner keeps a way in.
- Board quick-assess constraints adopted: single-zone Cloudflare token, socket proxy, secure headers, rate limit on the Authentik login, separate networks, forward-auth fails closed, Plex 32400 documented as a separate exposure, real-network checks recorded in the runbook Acceptance record.

## Plan Structure
- **Plan 03-01 (Wave 1)**: Traefik core, DDNS and admin routes -- Stand up Traefik v3 behind a read-only docker-socket-proxy with wildcard DNS-01 certificates, cloudflare-ddns, the lan-only and secure-headers middlewares in the int/public chains, *.int routes for every admin UI and the public Seerr route, plus the secrets script, verify-edge.sh, CI tests and the first half of the edge runbook.
- **Plan 03-02 (Wave 2)**: Authentik SSO, forward-auth and admin MFA -- Add Authentik (server, worker, Postgres) with blueprints for the domain-level forward-auth provider, the admins group, admin-only MFA and an invitation enrollment flow; put Authentik forward-auth into the int chain, publish auth.<domain> with its admin interface LAN-only, and extend verify-edge.sh, test-edge.sh and the runbook.
- **Plan 03-03 (Wave 3)**: CrowdSec, geo-block and LAN-port cutover -- Add the CrowdSec engine with the Traefik bouncer plugin and the geo-block plugin on the public chain, remove the temporary compose.lan.yaml admin ports, finish verify-edge.sh, update the architecture doc and Phase 2 runbook references, and complete runbook 04 with verification, acceptance record, rollback and troubleshooting.
