**`scripts/vm/30-split-4k.sh`** (executable) sources `common.sh` then `arr.sh`, runs `load_env`, and implements the spec contract "`scripts/vm/30-split-4k.sh`" exactly.
- Flags: `[--apply] [--undo <manifest>] [--help]`. The local parser runs first, then `parse_common_args`; unknown flag → exit 2.
- Env: `QP_4K_RADARR`, `QP_4K_SONARR` (default `Ultra-HD`). Resolve each to an id via `GET <base>/qualityprofile` on the 4K instance; if missing, `die` listing the names.
- Path mapping: in-container `/data/…` equals `$DATA_ROOT/…` on the VM; every `test -e`/`mv` uses the mapped path, every API payload uses the container path.
- **Plan:**
  - 4K test per file, as in the spec: `max(quality.quality.resolution, height from mediaInfo.resolution)` ≥ 2160, or `mediaInfo` width ≥ 3200. If quality and `mediaInfo` disagree about 4K, the title's action is `check` (listed, never moved).
  - Skip titles already tagged `4k-only` in HD (so a re-run plans 0 moves). Do **not** filter on `monitored`.
  - Movies: `GET /api/v3/movie` on `radarr`, `GET /api/v3/moviefile?movieId=<id>`; all files 4K → `move`. Movies under `/data/media/anime-movies` are excluded.
  - Series: `GET /api/v3/series` on `sonarr`, `GET /api/v3/episodefile?seriesId=<id>`; all 4K → `move`, some → `skip-mixed`, none → not listed.
  - Only the `sonarr` and `radarr` HD instances are split. For anime (`sonarr-anime`, radarr `anime-movies`) the summary only reports `anime-4k=<n>` titles with 4K files.
  - `dst` = `/data/media/{movies-4k|tv-4k}/<basename of src>`.
  - Write `$APPDATA_ROOT/.migration/split-4k-<ts>.tsv` (header row, tab-separated, mode 600) and print a summary: `[INFO] plan: <n> move, <n> skip-mixed, <n> check, anime-4k=<n> -> <tsv>`, then each `skip-mixed` and `check` title.
- **Apply:** preflight every `move` row first (dst absent, src present and under `/data/media/movies/` or `/data/media/tv/`); any failure prints every bad row and exits 1 with nothing moved. Then per row, as in the spec: `mv`, lookup + `POST` to the 4K instance, rescan + `wait_cmd`, ensure tag `4k-only` in HD, `PUT` the HD item unmonitored (and every season for series) with the tag, append to `split-4k-<ts>.manifest.tsv` (TSV columns + `new_id`). A failure after the `mv` of a row prints `[ERROR] row <n> partially applied; run --undo <manifest>` and exits 1.
- **Undo** reads the manifest, reverses rows in reverse order as the spec says, and is itself dry-run unless `--apply`.
- All mutations go through `arr_mutate`; the `mv` goes through `run`.
