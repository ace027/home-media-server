**`scripts/lib/arr.sh`** is sourced only. It has no shebang execution path, starts with `# shellcheck shell=bash`, and requires `common.sh` to be loaded first (it checks that `log_info` exists and dies otherwise). Implement exactly the spec contract.

- `DC=(docker compose --project-directory "$REPO_ROOT")`.
- `arr_port <svc>` and `arr_base <svc>`: `case` tables as in the spec. `sonarr*` means `sonarr|sonarr-anime|sonarr-4k`, and `radarr*` means `radarr|radarr-4k`.
- `svc_ip <svc>`: implemented as in the spec. Dies with `<svc> not running` when the result is empty.
- `svc_key <svc>`, per service:
  - `sed -n 's:.*<ApiKey>\(.*\)</ApiKey>.*:\1:p'` on `$APPDATA_ROOT/<svc>/config.xml` for the *arr instances and Prowlarr;
  - `sed -n 's/^api_key *= *//p'` for `sabnzbd.ini`;
  - `jq -r '.main.apiKey // empty'` for Seerr's `settings.json`;
  - `sed -n 's/.*PlexOnlineToken="\([^"]*\)".*/\1/p'` for Plex's `$APPDATA_ROOT/plex/Library/Application Support/Plex Media Server/Preferences.xml`.
  - Validate each against its spec regex. On a missing file or a mismatch: `die "missing/invalid API key for <svc>"`.
- `api <svc> <METHOD> <path> [body-file]`:
  - Build a curl config on stdin with `printf`: a `url = "http://IP:PORT<path>"` line, `header = "Accept: application/json"`, the key header (`X-Api-Key: …` for the *arr instances, Prowlarr and Seerr; `X-Plex-Token: …` for Plex; for SABnzbd the key is appended to the url as `&apikey=…`), and `header = "Content-Type: application/json"` when a body file is given.
  - Run `curl -sS --fail-with-body --max-time 30 -X <METHOD> -K - [--data-binary @<body-file>] -o "$tmp" -w '%{http_code}'`.
  - Capture with `code=$(curl …) || rc=$?` so curl's exit 22 on HTTP ≥400 (from `--fail-with-body`) does not abort under `set -e` before the error message.
  - If the code is 2xx, print the body; otherwise print `<METHOD> <svc> <path> -> HTTP <code>` to stderr and return 1.
  - The key only ever appears on curl's stdin.
- `sab_api <mode> [k=v…]`: builds `/api?mode=<mode>&output=json` plus `&k=<jq @uri of v>` for each pair, then calls `api sabnzbd GET`. `sab_api` is for read-only modes only. SAB changes (`set_config`, `del_config`, queue/history delete) go through `arr_mutate sabnzbd GET <path>` so they are dry-run by default and counted in `count_mutations`.
- `wait_cmd <svc> <json>`: reads `.id` and polls `GET <base>/command/<id>` every `WAIT_INTERVAL` seconds (default 3; tests use 0) for up to `WAIT_TIMEOUT` seconds (default 600).
- `arr_mutate <svc> <METHOD> <path> [body-file]`:
  - if `APPLY=0`, prints `DRY-RUN: <METHOD> <svc> <path> <jq -c body>`, redacting `apiKey`, `password` and any `*Key`/`*key` field value to `***` with `jq 'walk(...)'`, including inside `fields[]` where `.name` matches;
  - otherwise it calls `api`.
- `same_state <desired-file> <current-file>`: jq-normalizes both by projecting `{enable, implementation, name, syncLevel, fields: [fields[] | select(.name as $n | ["host","port","useSsl","baseUrl","prowlarrUrl","tvCategory","movieCategory","musicCategory","syncCategories","animeSyncCategories"] | index($n)) | {name, value}] | sort_by(.name)}`, skipping any field whose value is `"********"`. Returns 0 if equal.
- `count_mutations`: a global counter that `arr_mutate` increments.

**`scripts/ci/make-api-stubs.sh <dir>`** (executable). Its structure mirrors `make-host-stubs.sh`. It writes executable `docker`, `curl` and `ssh` stubs into `<dir>`, following the spec stub contract (`ssh` honors `STUB_SSH_RC`, otherwise runs its last argument locally).
- **docker stub:**
  - `inspect … <id>` prints `172.30.0.<n>`, where `n` is a stable number per service. Container ids are `id-<svc>`.
  - `compose … ps -q <svc>` prints `id-<svc>` if `<svc>` is in `$STUB_RUNNING`, otherwise nothing.
  - `compose … ps --status running --services` prints `$STUB_RUNNING` one per line.
  - `compose … config --images` prints `$STUB_IMAGES` (newline-separated; empty by default).
  - `compose … ps --format json` prints one JSON object per running service with `Service`, `State=running` and `Health` taken from `$STUB_HEALTH` (default `healthy`).
- **curl stub:**
  - Parses `-X`, `--data-binary @f` and `-o`/`-w`, and reads the `-K -` config from stdin.
  - Maps the IP back to the service, then strips `apikey=` from the query.
  - Logs `METHOD svc path` (plus ` body=<compact json>` for mutations) to `$STUB_LOG`.
  - Responds from `$STUB_FIXTURES/<svc>/<METHOD>_<sanitized path>.json`, where the sanitized path replaces `/ ? & = .` with `_` and collapses repeats. If that file is missing: `{}` for GET, empty body with 200 for other methods. `STUB_HTTP_<svc_underscored>=<code>` forces the code.
  - Writes the body to the `-o` file and prints the code for `-w`. Like real `curl --fail-with-body`, it exits 22 when the code is ≥400.
  - **Sequence support:** if `<file>.1`, `<file>.2`, … exist, successive calls return them in order (tracked in `$STUB_STATE`), so a re-GET after an update can differ.
