**`scripts/ci/check-min-versions.sh [compose-file]`** (executable). It follows `check-pinned-images.sh` for its structure: it sources `common.sh`, has `usage()`, and defaults to the repo's `compose.yaml`. It also takes `MIN_FILE` (default `$REPO_ROOT/config/min-versions.txt`).
1. Read the images with `COMPOSE_PROFILES=jellyfin docker compose -f <file> config --images`.
2. For each image `repo:tag` whose repo is listed, normalize both tags exactly as the spec says:
   - strip a leading `v`;
   - split off a trailing `-ls<N>` into `ls` (0 if absent);
   - remove any `-[0-9a-f]{7,}` segment.
3. Compare the versions: equal passes; otherwise `printf '%s\n' min cur | sort -V | head -1` must be `min`. If the versions are equal, compare `ls` numerically.
4. Print `BELOW-MIN: <image> < <min>` for each failure and exit 1. If no listed repo was matched at all, print `NO-IMAGES: no listed image found in <file>` and exit 1 (never pass vacuously). Otherwise print `OK: <n> images at or above minimum`.

**`scripts/ci/test-compose.sh`** (executable, `set -Eeuo pipefail`, runnable from the repo root, prints `ok <name>` per check, exits 1 on the first failure):
1. `cp -n .env.example .env` if `.env` is missing, then assert `docker compose config -q`, `docker compose --profile jellyfin config -q`, and `COMPOSE_FILE=compose.yaml:compose.lan.yaml LAN_IP=127.0.0.1 docker compose config -q`.
2. Assert `LAN_IP= COMPOSE_FILE=compose.yaml:compose.lan.yaml docker compose config -q` **fails**, with a message containing `set LAN_IP`.
3. **Single /data:** with `docker compose --profile jellyfin config --format json`, no service may have more than one volume whose `target` starts with `/data`. The only allowed `/data` subpath target is `/data/media`, and it must have `read_only: true`.
